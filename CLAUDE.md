# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

FumetoReaderPlus is a manga/comic reader with library management (local imports + YACReader/Komga/Kavita servers) and AI translation (off-device LLM providers, or fully on-device). It is a SvelteKit 5 + TypeScript SPA running inside a Tauri v2 Android WebView, with native Kotlin/C++ accelerators and a thin Rust layer. **Android is the product** — the desktop target exists but is shelved. Offline-first: SSR is disabled and the static adapter emits a single `index.html` for Tauri to load.

The architecture deep-dives are being re-published gradually after the open-sourcing cleanup; until then, this file is the canonical orientation.

## Commands

```bash
npm run dev              # Vite dev server (frontend only, in a browser)
npm run build            # Static SPA build → build/
npm run check            # i18n compile → svelte-check over src/ → native-strings check

npm run tauri:android-build -- --debug   # Android debug APK (for device testing)
npm run tauri:android-build              # Release build (requires signing)
npm run build:android    # SPA build + prune-android-embed (used by android builds)
```

Android builds need `ANDROID_HOME`/`NDK_HOME` exported and **JDK 21** (newer JDKs are not supported by this Gradle). Node: `.npmrc` sets `engine-strict=true`, and the dependency tree's `engines` ranges admit Node 22/24/26 but reject 20, 23 and 25 — `npm ci` fails outright on those (CI pins 24 for exactly this reason; see the comment in `.github/workflows/build.yml`).

`src-tauri/gen/android/` is Tauri's generated project, but the Kotlin sources under `app/src/main/java/com/fumeto/reader/`, `app/build.gradle.kts` and `proguard-rules.pro` are git-tracked customizations — re-running `tauri android init` overwrites them; restore with `git checkout -- src-tauri/gen/android/`. `src-tauri/tauri.android.conf.json` swaps the Android `beforeBuildCommand` to `npm run build:android`, and `build.gradle.kts` drives the llama-bridge CMake build, which is CPU-only on every ABI: `libfumeto_llama.so` must never NEED a vendor library (an OpenCL link once kept on-device translation from loading on devices without a public `libOpenCL.so`).

The only CI (`.github/workflows/build.yml`) builds **desktop** Tauri bundles (macOS/Windows/Linux) on a `v*` tag push or manual dispatch and opens a draft GitHub release. It runs no tests and no Android build; `release:record` creates `v<version>-vc<code>` tags, so pushing one triggers it.

### Release

`npm run version:set -- X.Y.Z` writes the version to all three carriers (`package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`; `versionCode` = major·1 000 000 + minor·1 000 + patch) — never bump one by hand. `npm run release:android -- --aab` wraps the whole build: `release:preflight` (the three versions agree, the versionCode is not already in the ledger, clean worktree, `i18n:draft:check`, then `check`), `tauri android build` with `VITE_FUMETO_DEBUG_UI_FIXTURES=0`/`VITE_FUMETO_PSEUDOLOCALE=0` pinned, and `release:collect` into `dist/android/`. The default is an APK; Play needs `--aab`. `npm run release:record -- --artifact dist/android/<name> --track <internal|closed-testing|open-testing|production>` runs **after the Play upload, not after the build** — it appends to `release-ledger.json` (which is what marks that versionCode spent) and creates the `v<version>-vc<code>` tag. Keystore and `key.properties` are gitignored. Workflow is trunk-based on `main` with short-lived branches.

## Architecture

### Big picture

One route (`src/routes/+page.svelte`); `appView` switches between `catalog | tabs | reader | settings`. All product state and business logic live in the WebView (TypeScript). Native code is **stateless accelerators plus lifecycle services** — nothing durable lives in Kotlin/Rust. Durable data is in Dexie/IndexedDB (DB name `fumetoreaderplus`, kept for user-data preservation) plus app-private files for downloaded models.

Kotlin bridges injected into the WebView (`src-tauri/gen/android/.../MainActivity.kt`):

- `__fumeto_android` — insets, content-URI display names
- `__fumeto_back_handler` — not an injected object but a JS global the frontend defines; the Kotlin back-press callback calls it and only exits the app when it returns `true`
- `__fumeto_ppocr_native` — PP-OCR det/rec via onnxruntime-android (preferred over WASM)
- `__fumeto_rtmdet_native` — rtmdet-manga layout detection
- `__fumeto_sfx_native` — sound-effect filter inference on crops the WebView cut (the WebView keeps the cropping)
- `__fumeto_encdec_native` — the on-device Japanese-to-English encoder-decoder translators (tokenizers, both ONNX graphs, page windowing and beam search in Kotlin)
- `__fumeto_llama` — Hy-MT2 GGUF inference via `libfumeto_llama.so` (vendored llama.cpp under `src-tauri/llama-bridge/llama.cpp` — a plain checkout, NOT a submodule; pinned SHA in `llama.cpp-version.txt`)
- `__fumeto_service` — foreground services (background batch translation keep-alive, model residency); the JS translation loop keeps running unchanged, no logic moves to Kotlin

Each native bridge has a WASM/JS fallback path so the app still works in a plain browser (`npm run dev`) — except the encoder-decoder translator, which is Android-only: where its bridge is absent, Settings does not offer it.

### Key invariants (violating these is a bug)

#### Core

- **Overlay data is schema V2 only** (`PageOverlayDataV2`, content-hashed IDs, deterministic render plans — ADR-0006). Legacy records are purged on read, never rendered.
- **All remote/CPU work goes through `WorkCoordinator` lanes** (`src/lib/work-coordination/`, ADR-0001). YACReader transport is single-flight per server — the Qt server crashes on concurrent connections.
- **Cancellation is a first-class contract**: `AbortSignal` threads through detection → translation → layout; the reader controller distinguishes user-cancel from supersession.
- **Dexie migrations are append-only**: add new versions in `src/lib/db/schema.ts`, never edit existing ones.
- **Tabs are explicit-only**: opening/reading a volume never mutates the tab list; the Continue Reading strip is derived from `last_read_at` via one global query (`src/lib/catalog/continue-reading.ts`).
- **Book reader navigates in whole-book pages**, not spine sections; sections are persistence-only. Never navigate by writing `currentPageIndex`.

#### Catalog and remote libraries

- **No auto re-sync of remote libraries**: after initial indexing, manual Scan is the only refresh. The gate is `catalog_index_state.remote_index_completed_at`, stamped only by a crawl that finished with zero failures, and read through `remoteStartupSyncPlan` by all three providers. Deliberately NOT `completeness`, which the catalog migration writes as `'ready'` for any library that has rows.
- **A folder's freshness lives on `contentsFetchedAt`, never `lastFetched`.** `lastFetched` records when a folder ROW was written — i.e. when it appeared in its parent's listing. Only `contentsFetchedAt` means "this folder's own contents were fetched".
- **Server-side deletions are propagated on manual Scan only, and only on positive confirmation.** Absence from a listing merely nominates; deletion requires the server to answer `not_found` for that exact item (`src/lib/catalog/remote-prune.ts`). Any other outcome — a 200, a network error, a 5xx, an auth failure — leaves the row alone.
- **A library being deleted is fenced, and every provider must check the fence** (`src/lib/catalog/remote-library-fence.ts`). `assertLibraryWritable` before any write, in the crawl loop as well as at the entry point — a crawl runs for minutes and the delete is a tap. A volume written after `deleteLibraryData` has read its volume list survives under a `library_id` nothing lists: it renders nowhere, no delete path reaches it, and nothing sweeps in that direction.
- **A crawl that resolved is not a crawl that succeeded.** Report the outcome through `reportRemoteSyncOutcome(libraryId, failures)`, never `reportRemoteSyncSuccess` unconditionally — clearing the failure entry is the user's only sign anything went wrong, and for Komga/Kavita a failed crawl also withholds the completion stamp, so the next launch silently re-crawls.
- **Deleting a volume goes through `deleteVolumeRowsInTransaction`** with `volumeScopedTables()` as the transaction scope (`src/lib/catalog/catalog-repository.ts`). Never hand-roll the cascade: Dexie throwing on an undeclared table is what keeps the scope and the deletes from drifting apart.
- **A remote sync never overwrites a user-owned field.** Guard on record EXISTENCE, not `existing?.field ?? …` — the reader's quick toggle writes `undefined` to mean "follow the global default", so a `??` chain re-pins a volume the user deliberately un-pinned.

#### Overlay layout: geometry and rendering

- **A shared region is carved by usable AREA, not by height** (`partitionByDemand` in `src/lib/overlay-layout/geometry.ts`). Two utterances in one balloon, or several vertical columns in one bubble, get bands proportioned by the ink each can actually hold — a band across a waist or a taper holds a fraction of what a mid-body band of the same height does. Boundaries snap onto necks, and the neck itself is given to neither utterance. Where a container has as many lobes as utterances, each is matched to the lobe its own SOURCE sits in; source position is ground truth and needs no assumption about reading direction.
- **"Two bubbles drawn conjoined" has one definition**: `polygonLobeSplit`. `polygonWaistSplit` is a two-lobe wrapper over it. A waist is narrow from BOTH sides — a notch, narrow from one, is a dent and must not split.
- **One utterance spanning a conjoined balloon's lobes is threaded through them** (`threadedLobes`, `threadedHorizontalLines`). When a balloon's only item has source lettering in two or more of its lobes, its window lays the text out with one stack of rows per lobe and none across the waist; per-lobe windows are not offered for it, because confining it to one lobe is exactly what this replaces (one lobe whitewashed and empty, or text centred across the waist with one word per row). The text is split where a sentence ends, at the boundary whose share of the text best matches the share of the source drawn in the first lobe, each half centred in its lobe; a flow from lobe to lobe is the fallback, and after growth the sentence split is kept whenever it holds 85% of the flow's size. A lobe's tapering end rows (under half its widest row) stay empty.
- **Hyphenation is English-only, and `'und'` is not English.** The patterns are hyph-en-us and the document's locale is the translation TARGET. `overlayTargetLocale` is the single resolution point — the adapter's `'und'` fallback would silently stop hyphenating for English readers, and `validate:overlay-layout` fails if a construction bypasses it.
- **`tailPolygon` is dead code in production.** Nothing in `src/lib` writes it, so no document the app builds carries one and the planner's tail-exclusion never runs on a real page. A development bench re-attaches it after the adapter, deliberately and visibly, so the probe survives without reading as something production does.
- **`'unknown'` is not "not dialogue" — it is "we do not know".** The adapter launders both `borderless` (unenclosed narration, classifier confidence 0.66) and a genuine classification failure (0.45) onto that one type. Only SFX may be suppressed from the reader's review affordances; suppressing `'unknown'` gave the least help to the text most likely to be laid out badly. `OverlayItemV2.classificationConfidence` separates the two, is quantized to 0.01 because it enters the layout input hash, and is written only when the production classifier decided the type — a provider label is not a measurement, and absent confidence means "not uncertain".
- **A stacked band is exempt from every score term that asks about the item's own source.** `displacement`, `sourceUncovered` and `hyphenatedBreaks` all do, and a band's position, extent and width are the shared REGION's — charging a member for them measures someone else's decision. Each was worth measurable damage when left in: 2–4 points, 15 points, and one member of a stack dropping 33.5px/1 hyphen to 28.25px/2.
- **An unbounded item's ERASURE is sized by the source; its CARD stays sized by the ink.** They are separate shapes for a reason. A card tightened onto horizontal English cannot cover the tall narrow run of vertical Japanese it replaces, and widening the card instead would inflate `boxGrowth` (weight 12 for free layout), protected-art scoring and collision — making exactly the placements we want look expensive. The erasure is one rectangle per detected column, never one over their union: the gutters between a run's columns are artwork and are usually more than half its width.
- **A soft edge on an erasure ramps OUTWARD.** Feathering inward puts the translucent bands over the lettering they exist to erase, and fragments of the original show back through around the edge of the block. Peak coverage is reached at the source's own boundary; the ramp lands on the paper beyond it. Since policy-31 the peak is deliberately translucent (0.8, fading to 0.05 at the fringe — `FEATHER_CORE_COVERAGE`/`FEATHER_EDGE_COVERAGE` in `presentation.ts`): an unbounded whitewash sits on artwork, and the art ghosting through at 20% is the intended look, not a compositing bug.
- **The feather is a fixed step count with explicit alphas, never a blur.** SVG `fill-opacity` and canvas `globalAlpha` composite source-over with identical arithmetic; an SVG filter and `ctx.filter` do not match, and three surfaces paint the same plan.
- **Font sizes on a page are never matched against each other (policy-33).** Each item fills its OWN region: a short line in a big balloon is as large as that balloon holds, however small its neighbours' text is. The page-median clamp (`harmonizePageFonts`), the growth cap that mirrored it and the beam's same-style size penalty are gone — together they left short lines at 3–5% of their balloon on dense pages. After assignment `maximizeSelectedFonts` grows every placement to the largest size its region holds (balloon contour, band, source-region window, the user's rectangle; free text inside its FOOTPRINT, the box of its source lettering together with the card it was placed with), and records it as `maxFontSize`. Only sound effects keep their prominence cap through growth.
- **Growth changes the size and nothing else (policy-34).** It keeps the winner's typography profile and stack position, and free text keeps the footprint's width and height. Balloon text may grow in any window of its own balloon the candidate search accepted with that profile (the outline and margins are the same; which window won the beam is an accident of the ladder), and takes the largest. Policy-33 let it switch to a tighter profile, an off-centre stack or another search window, bounded free text by its erasure's AREA, and lifted the ladder's 128px top and free text's glyph cap: the overlays changed shape — balloon text crept to 2px from the outline, unenclosed text became a strip up to twice its source's width — and readers saw the boxes stop following the original text. The candidate ladder (128px sampling top, free text capped at the source glyph size) decides the shape; it is not a cap on the final size, because growth takes every item past it.
- **A line's width is its ink.** The Pretext adapter reports a line without the whitespace `pre-wrap` lets hang past its edge (`hangingWhitespaceWidth`), and re-asks Pretext with a lower limit when it returns a line wider than its row (0.0.8 lets a second soft-hyphen opportunity replace a fitting first one). Every consumer — the fit check in `runPlans`, the centring, the contour test — compares that width with the row. Counting the hanging space made lines that fitted look 3–6px too wide: on real pages most smaller sizes were rejected, a balloon's text came out at 6px "degraded", and what fitted looked non-monotone in the size.
- **Any pass that re-lays text out must re-tighten an ink-derived card.** `renderedRect` for a free item is `tightInkRect` measured at the size assignment chose; `maximizeSelectedFonts` then grows the font and the ink outgrows the card. The fuzz gate catches it as a clipping violation, which is what it is.
- **No pass may buy a font size with a cut word.** `maximizeSelectedFonts` refuses a growth that breaks a word, and `maxFontSize` is the largest size without one. `horizontalLines` fills rows from the top of its stack, and in a round balloon the top row is the narrowest, so before it accepts an emergency break it tries each shorter stack, which sits nearer the middle (policy-32); a one-word answer once came out as "Su / re.".
- **A size the user pins is placed exactly, and the editor offers only sizes that fit.** A pinned `referenceFontSize` bypasses the readability floor and may use any spacing profile; if the box can no longer hold it (it was resized under it), the planner falls back to the sizes up to it rather than dropping the item. The editor's font slider runs from a small page-relative floor to the plan's `maxFontSize` and starts at the size actually drawn. What fits is **not monotone in the size** (a line wraps differently at every size, and in a round balloon a smaller size can fail where a larger one fits), so every item's maximum is measured from the top down — a 1px scan from an analytic ceiling (the ink the placed lines need per pixel of size against the region's area, and a text with no break opportunity against its width), a bisection to the lowest failure, and then the larger sizes the candidate search already accepted in the same rect and profile — rather than climbed from the placed size (the climb alone under-measured 11 of 46 bench boxes, one by a third; a 12% geometric scan stepped over fitting bands a pixel or two wide). A pin the candidate ladder fell short of is placed at its exact size in any of the item's regions that holds it, and the slider's end moves only when the text or the box changes.
- **Lettering already in the target language is left as drawn** (`isAlreadyInTargetLanguage`, on-device pipeline). For an English target, a block with Latin letters and no kana, kanji or hangul gets no model call and no overlay: a handwritten "NOTEBOOK" came back as "Notebook" under a white plate. A region the user draws is still translated.
- **A surface that cannot offer the translation must not erase the source** (the reveal contract). Paged and long-strip both offer tap-to-reveal; CBZ export cannot, so export leaves the original readable rather than whitewashing it.

#### Detection and balloon grouping

- **Two balloon instances for one balloon are resolved by CONFIDENCE, not size.** rtmdet's box-IoU NMS keeps a lobe of a conjoined balloon (box IoU ≈ 0.3 against the whole), usually at a score just above the 0.35 threshold; `assignBubble` then calls every column inside both "ambiguous" and refuses to group any of them. `suppressNestedBalloonInstances` (≥ 0.9 inside, area within 4× — the same scale `assignBubble` uses) keeps the more confident instance, and runs in both segmenters AND at the grouper's entry so cached replays see it. Measured on real pages: in 3 of 16 nested pairs the LARGER instance is the ghost, so "drop the small one" is wrong.
- **One balloon is one utterance; the balloon is the grouping evidence, not the gaps between its columns.** Two components well inside the same detected balloon (`BALLOON_MEMBER_OVERLAP`, ≥ 0.5) merge on direction, orientation and the column pitch alone (`xGap ≤ 2.1` glyphs — within-utterance columns measure ≤ 1.75, two speakers sharing a conjoined balloon 2.93): a staggered column that starts below where its neighbour ended still joins, emphasis set up to 3.5× larger still joins, a small fragment (ruby, a mark, a speck the detector boxed) joins at any size — kept apart, one was translated as an utterance of its own and given a band of the balloon, and outside balloons a short reading set right against its line (furigana: 1.6–4.5× thinner, under 0.6 of the line, touching it on the reading side — `rubyBeside`) joins that line, where the extractor's furigana filter drops its text — kept apart, a title's reading was translated and set over the title, and no bbox-area cap, span cap or row split applies inside a balloon — the balloon bounds the text. A reader's device had 31 same-speaker balloons cut in two by exactly those four gates, and the reviewed labels put every one of those quantities on the one-group side. A component only leaning into a balloon (overlap < 0.5, a sigh drawn across the rim) never joins its members (`balloon-rim`). Rows of columns are one group read row by row: `COLUMN_ROW_GAP_GLYPHS` (0.85; column-cuts ≤ 0.5, rows ≥ 1.20) decides READING ORDER only — a split on it shipped for one day and contradicted every reviewed label it touched.
- **A set block of free text is one passage, and a block's fragments read from the right.** Outside a balloon the grouper refuses a cluster past 8% of the page (a guard against snowballing scattered lettering), but a block whose lines share a direction and a glyph size (≤ 1.35×), start on one line (tops within 1.5 glyphs), never partly overlap across the line axis and are packed densely (`isTextBlock`) is exempt up to 35%: a narration block of a few long columns passed 8% and was cut into pieces that were translated, and laid out, as unrelated texts. The page sort bands groups by their CENTRE, so the longest column of a block — often its first — sorted after the columns to its left; fragments of one free column block (overlapping along their height, within 2.1 glyphs, each ≥ 2.5 glyphs long, not SFX) are therefore emitted as a unit from the right and marked `continuesPrevious`, and the layout stacks a free column run's bands right to left by source position rather than by stored order, which also corrects pages grouped before the fix.

#### On-device models

- **The manga guidance blocks are generated, never hand-edited** (`scripts/generate-manga-guidance.mjs` → `llama-bridge/manga_guidance.h`, `src-tauri/src/manga_guidance.rs`). They are the exact per-target terminology the Hy-MT2 v3 fine-tune trained on; editing one moves the prompt off its training distribution. `--check` re-derives them from the frozen machine-local fine-tune config (`FUMETO_DATASET_CONFIG`) and fails on drift. Guidance is keyed on the language **code**, so "zh-Hans" and "Simplified Chinese" cannot disagree.
- **Every language the on-device picker offers must exist in both native name tables.** `getLangName` falls back to the raw code, so a missing entry ships a prompt reading "into zh-Hans" with nothing failing. The C++ and Rust language tables must stay in sync.
- **The llama worker count is one thread per fast core (clamp 4..6), read from `MIDR_EL1` at bridge init — never a per-SoC table and never an affinity mask** (`src-tauri/llama-bridge/cpu_topology.h`). ggml's per-op barrier runs at the slowest worker's pace, so a sixth thread on a Snapdragon 8 Gen 2's five fast cores cost 10 % and made throughput unstable; pinning the right count to the fast cores measured identical to leaving the scheduler alone, and the Snapdragon 8 Elite has no little cores at all, so any SoC-name rule is wrong in both directions. Unknown and unreadable cores count as fast (degrades to the old fixed 6, never below). Six is the cap on measurement, not on the old trial: on the Snapdragon 8 Elite's eight fast cores generation is flat from 4 threads up and 8 threads buys 11 % prompt speed — about 5 ms of a bubble — for every core the WebView and OCR would otherwise have. Every decode step then caps that count at the CPUs the app may run on right now (`sched_getaffinity`, read, never set): One UI moves a busy background app — foreground service and all — into a four-core cpuset, often mid-bubble, and six workers on four cores made one bubble take 148 s and a page 209 s instead of 8.
- **The bundled models' load path is checked first and must stay byte-identical.** `nativeLoadModel` resolves a template mode — Hunyuan-dense, then the model's own embedded template, then a user-supplied prefix/suffix, then rejection. Only a model that fails the Hunyuan check reaches the newer branches, and BOS is force-prepended only for Hunyuan (others honour `llama_vocab_get_add_bos`).
- **A model's prompt family is declared by its catalogue entry, never inferred from the file.** `HYMT2_VARIANTS[...].promptProfile` travels to the native load, and the profile decides the instruction, the chat wrapping and the sampler together. Index-Translate (`index_translate_prompt.h`) takes a Chinese instruction in plain ChatML with no think block and decodes greedily, ignoring the temperature setting; under Hy-MT2's prompt the same file still translates, measurably worse, and nothing reports it. A file that cannot follow the requested profile is refused at load. The profile lives in the Android bridge; the desktop Rust bridge accepts Hy-MT2 files only and refuses this one.
- **Translation paths ask `isActiveHyMT2ModelLoaded()`, never "is a model loaded".** A download validates its file by loading it and an import probes the same way, so the resident model can be a different file — or the right file under the wrong options — than the one selected. Every load goes through `loadOptionsFor(variant)` so validation and translation cannot drift apart.
- **The `model` stored with an on-device translation comes from `onDeviceModelLabel()`** (`translation/on-device-model-label.ts`), for the variant selected when the work was asked for. The page pipeline, the volume job and the single-region path each write one, and each used to spell out the stock model's name, so a fine-tune's pages were recorded as the stock model's. The names go into the user's library: `stock` keeps `hymt2-1.25bit`, and a name that has shipped is never renamed.
- **A model with recurrent memory reuses its prompt prefix through a state snapshot, not a KV rewind** (`recurrent_prefix.h`). Qwen3.5 is a hybrid: `llama_memory_seq_rm` refuses to cut into a recurrent state, so the bridge copies that state at the end of the instruction and puts it back before the next bubble, then trims the attention half as usual. The rewind is exact, but a prompt decoded in two batches is not bit-identical to the same prompt decoded in one — the snapshot path always splits at the instruction, so its output is self-consistent and differs in low-margin tokens from a single-batch reference. Dense models never enter this path.
- **The sound-effect model is downloaded, never bundled, and it ships together with its calibration.** `SFX_MODEL` (`detection/sfx-model-manager.ts`) names the file after `SFX_FILTER_CALIBRATION.model` and pins its URL, size and sha256; a new model changes all of them and the strength anchors in one commit — anchors derived for another model's scores silently change what every strength means. The filter is optional by construction: with SFX overlays shown, a strength of 0, or no model, pages are not scored and the layout rules decide alone, and nothing about it gates translation.
- **The sound-effect model is published as fp16 storage with fp32 compute, and it runs on the plain CPU provider natively.** A full fp16 conversion loads on desktop and in WASM but not in Android's ONNX Runtime: its optimizer fuses the head's GELU into an fp16 `com.microsoft.Gelu` that has no CPU kernel there. Storing the weights as fp16 initializers, each behind a `Cast` that is folded at load, keeps the 17.5 MB download while every runtime executes a plain fp32 graph. XNNPACK is deliberately not used: on this graph it returned a one-element output for a batch of four crops, so `SfxFilterEngine` uses the CPU provider and still checks every output holds one score per crop.
- **The layout model emits only the balloon masks the native engine traces.** ONNX Runtime's Java API hands every output back as a copy in the Java heap, and the mmdeploy export ends in 100 full-size fp32 masks — 400 MiB a page, past the ¾-of-heap line at which Android destroys an Activity it cannot see, which the Rust side turns into the app exiting under a background batch. The published file (`rtmdet-manga-layout-1024-balloon-masks.onnx`) selects the balloons scoring ≥ 0.35 in-graph and emits them as uint8 with their detection indices, about 1 MiB a balloon. A new layout model must keep its outputs that small; `RtmdetLayoutEngine` reads the full-mask form only from a file downloaded before the switch.
- **The encoder-decoder translators are catalogue entries, downloaded, pinned and verified natively.** `fumetotranslate` (and the model it replaced, `manga-ja-en-v1`) sit in `HYMT2_VARIANTS` with `kind: 'encdec'`, so the picker, the stored label and the language-pair warning treat them like every other choice, and every translation path branches on `isEncDecVariant` before touching llama.cpp. `ENCDEC_MODELS` (`translation/encdec-model-manager.ts`) pins each model's five files to one Hugging Face revision with their sizes and sha256, in a folder of its own; the WebView sends that manifest with every call and `EncDecEngine` checks it once per set of files on disk, deleting a file that fails. Both decode with beam 4: greedy decoding scores nearly the same by chrF++ and COMET and loses clearly in blind review.
- **FumetoTranslate reads a page; which way is the `encdecMode` setting, and the label records it.** `meta.json` tells `EncDecEngine` a page model (`config.page`) from a line model. Page mode sends a page's model blocks in reading order in ONE `translatePage` call: the engine encodes them together (`<s> line <sep> line … </s>`, windowed to the model's token budget by `EncDecPagePlanner`) and decodes every line in one batch (`PageBeamSearch`), each told its line through `rel`; the blocks skipped as meta, low-confidence, sound effect or dictionary sound effect are neither translated nor context. A drawn region sends the whole page with `decode` naming only itself. Line mode is a page of one line per block. The stored label is `on-device-fumetotranslate-page-…` or `-line-…`; a volume job keeps the mode it started with. A page-model call is cancellable between decoder steps (`cancel(callbackId)`), so an aborted page stops natively. Results match the reference implementation up to numeric drift (on-device parity test, `EncDecPageParityInstrumentedTest`, fixtures outside the repo).
- **A replaced encoder-decoder model hands off only once its successor is ready** (`translation/encdec-handoff.ts`). `replacedBy` on a deprecated entry names its successor. The old model keeps translating until the successor's download has finished and passed a probe; then a selection of the old model moves to the successor and the old folder is deleted, never while a volume job runs (it runs again when the last job ends, and at startup). Settings' open draft follows the move (`onEncDecHandoff`), or its next apply would select the deleted model. Its owner is offered the successor once (`offerEncDecReplacement`), never blocking a translation.
- **A deprecated model is never taken from someone who has it.** `deprecated: true` removes a variant's Download button and hides its card unless it is downloaded or selected; it keeps translating and its records keep their label. A selection of a deprecated model that is NOT on the device is moved to `recommendedHyMT2Variant` (FumetoTranslate for Japanese → English where it runs, v5 elsewhere, v3 for every other pair) at startup and when that model is deleted — it could only ever fail, and that is how the recommendation reaches profiles still on the old default. A fresh install is seeded with the same function, which also places the Recommended badge; any other existing selection is never changed.
- **A user-imported model is stored under a fixed filename, never the picked display name**, which is untrusted text from the document picker. Deleting it clears the settings record as well as the file: `activeHyMT2Variant()` degrades a `'custom'` selection to stock only while no record exists.

#### Localization

- **Text order is the source language's, never the page-turn direction.** The reading-direction setting (default left-to-right) decides only which way pages turn. Box IDs — the order the translation reads a page in and the order overlays stack in — are numbered right to left, top to bottom for a Japanese source whatever that setting says (`textReadingDirection` in `ppocr-grouping.ts`, the one place it is decided); other sources follow the page direction. Numbering Japanese boxes by the page setting fed the page model a page's lines out of order and stacked one passage's overlays jumbled.
- **Two language axes, never coupled after first run.** `settings.uiLocale` is what the menus say; `targetLanguage`/`onDeviceTargetLang` is what the manga becomes. A fresh install seeds the target from the UI locale ONCE (`pt-BR`→`pt`); changing the UI later never touches it. `getLanguagePromptName` (in `settings/language-prompt-names.ts`, a prompt module the gate skips) is frozen English because the Hy-MT2 fine-tune saw those names — pickers use `getLanguageDisplayName` from `$lib/i18n`.
- **Every user-facing string is a message; stores and records hold codes.** Components call `m.<key>()` from `$lib/paraglide/messages.js` (generated, gitignored; `npm run i18n:compile`); persisted/store text is a `UserMessage { code, params }` rendered by the component, and every code has a `RENDERERS` entry.
- **A drafted locale that is behind its English source never ships.** Each draft carries the sha256 of the source it was made from (`messages/<locale>.meta.json`); `npm run i18n:draft:check` (offline, run by `release:preflight`) fails on stale/missing/orphan keys unless `messages/stale-acknowledgements.json` names a reason and an `expiresBefore` version. `npm run i18n:draft` re-drafts only what changed and writes only what the validator accepts (placeholders, tags, the locale's plural categories, glossary, register, length, punctuation). Never-translate terms are `messages/glossary.json`, not prose in a prompt; a hand correction is marked `reviewed` so a re-draft cannot overwrite it.
- **A library import judges each pick on its own, and a pick that fails leaves nothing behind.** `importToLibrary` never copies over a path `library_imports` already records: the scanner reads a rewritten archive as changed and re-imports it with `clearDerivedData`, which discards every translation made on that volume. It removes a copy the scan could not index (left in the folder it fails every later scan and nothing can open or delete it), counts only the scan failures on its own copies, and deletes an original only once its copy is a volume. `triagePicks` turns away a pick whose name ends in another file type before a byte of it is read — the picker's type filter is advisory on Android — while a name with no extension goes through and the archive parser decides.
- **An answer from a native dialog can sit in the runtime until the next native call.** On Android a picker's result arrives while the app is still behind the picker, and the runtime sometimes does not wake for it: the `open()` promise stays pending, the import dialog stays on its first step as if nothing had been picked, and the answer is delivered whenever some other native call happens to be made. `installNativeResultWake` (`src/lib/device/native-result-wake.ts`, installed once in `+page.svelte`) makes a trivial native call each time the page becomes visible again, which releases it. Every flow that awaits a native dialog depends on that hook, so it is never tied to a view or a feature.
- **A background batch needs its WebView kept awake, and its page loop must not wait on the Tauri runtime.** Within about a minute of the app leaving the screen Chromium stops a hidden WebView's timers, IndexedDB and fetch callbacks; microtasks and the Java bridges' callbacks still run, so a batch got through a page or two and then parked on its next checkpoint until the app came back. While `TranslationForegroundService` runs, `MainActivity.onStop` re-announces the WebView's window as visible, and the service's stop hides it again if the app is still out of view. Separately, an answer the runtime holds while the app is out of view (above) stalled pages the same way, so a call made on every page — the vision-model check was one — must not reach the runtime.
- **A mobile bar segment is an icon from `components/ui/Icon.svelte` over one word, and the grid is what makes the segments one width.** `MobileRegionReviewStrip` is `grid-cols-4`; what a segment does, in full, is its `aria-label`, and a count is a badge hung off the icon's corner. A quarter of a 360dp screen is 79px, so the strip's labels are 10px and each must fit that in all eight UI locales — the longest today is Spanish at 69px. `h-5`/`w-5` are 22.5px here, not 20: the root font size is 18px.

### Domain map (src/lib/)

- `db/` — Dexie schema + singleton. `catalog/` — catalog projection, Continue Reading, virtual windowing. `library/`, `yacreader/`, `komga/`, `kavita/` — sources and server clients. `import/` — ZIP/RAR/PDF extraction into IndexedDB.
- `reader/` — `PageSource` abstraction (local/remote/prefetched implementations via `page-source-factory.ts`), LRU image cache, page-mode detection. `book/` — EPUB reader on vendored `foliate-js` (`src/lib/vendor/foliate-js`); `media_kind` absent ≡ comic, `'book'` ≡ EPUB (`book/media-kind.ts`). `panzoom/` — gesture handling with explicit content dimensions.
- `detection/` — PP-OCRv6 detection + CTC recognition (ONNX), YOLO bubble segmentation, spatial merge. The learned sound-effect filter (`sfx-filter.ts`, a downloaded crop classifier: native ONNX Runtime on Android, onnxruntime-web elsewhere and as the fallback) scores unenclosed groups; the overlay gate applies the reader's strength at layout time. Detection and recognition use **different image normalizations** — mixing them fails silently. Raw regions feed the recognizer; merged regions feed the overlay.
- `translation/` — provider adapters (OpenRouter/Claude/OpenAI-compat/local) behind `llm-client.ts`; region/full-page/2-pass volume translation (checkpointed per page, resumable); non-destructive revision; Mode 1/2/3 context (isolated / page / rolling work context). On-device pipeline is PP-OCR + a llama.cpp GGUF (Hy-MT2 family, Index-Translate) or a native encoder-decoder translator — ML Kit was removed and both settings axes are hard-pinned (`onDeviceOCRProvider: 'ppocr'`, `onDeviceTranslationBackend: 'translategemma'`; the `translategemma` literal is kept for settings-migration stability and means Hy-MT2).
- `overlay-layout/` — V2 canonical render-plan engine (placement, fills, bidi, baked cache). `export/` — CBZ export rendering overlays via the same canonical plans.
- `tabs/`, `controllers/`, `navigation/`, `stores/` — UI state machines. Components use Svelte 5 runes; `stores/` uses classic `writable`/`derived`.
- `regions/` — guided regions (user-drawn boxes: draw session, cropper, per-region translation run). `billing/` — Play Billing bridge, entitlement policy, `PRO_FEATURES`. `i18n/` — locale tables, `getLanguageDisplayName`, `UserMessage` renderers; `paraglide/` — generated message functions (gitignored). `diagnostics/` — always-on error ring, boundary and report. `benchmark/` — the in-app PP-OCR/model-candidate benchmark host that the e2e specs drive. `work-coordination/` — the lanes.
- There is no feature flag for overlay v2 — it is the only overlay system. Desktop-only paths (Rust llama commands, `library-watcher`) are inert on Android.

## Conventions

- **Svelte 5 runes** (`$state`, `$derived`, `$effect`) in components; classic store API in `stores/`. `$lib` → `src/lib/`. No SSR (`+layout.ts` sets `ssr = false`, `prerender = false`).
- **Tailwind CSS v4** via `@tailwindcss/vite`. 12 color schemes override `--color-primary-*`/`--color-surface-*` at runtime (`settings/color-schemes.ts`; regenerate with `npm run schemes:generate`). Safe-area CSS vars: `--sat`, `--sab`, `--viewport-height` (Android reports `env(safe-area-*)` as 0 — use the vars).
- **ONNX models** live in `static/models/`, ONNX Runtime WASM in `static/wasm/` — loaded at runtime, never imported; ONNX Runtime is excluded from `optimizeDeps`, workers use `format: 'es'`.
- **API keys** are AES-256-GCM encrypted via Web Crypto (`settings/secure-storage.ts`); settings use localStorage with filesystem fallback. Two rules here are load-bearing, because breaking either loses every stored secret *silently*:
  - **The device key may be generated only on positive proof it is absent** (an `exists()` check). "I could not read it" must never be treated as "there is none" — generating over a key that is merely unreadable orphans every ciphertext, and decrypt failures surface as an empty string, so the user is told their key is unset and re-entering it makes the loss permanent. On an unreadable key `secure-storage` fails closed and says so. Fail-closed applies only where a filesystem exists: the Tauri fs plugin imports cleanly in a browser and only its *calls* fail, so no Tauri host means "absent" by construction.
  - **The Pro entitlement cache and every encrypted secret are mirrored to `$APPDATA/secure-store.json`** (`settings/durable-store.ts`), because Android can evict WebView localStorage. The mirror's three-state status (`loaded` / `unreadable` / `unavailable`) is the safety mechanism — `unreadable` must never be read as "empty", and the entitlement restore is upgrade-only so a failed check can never revoke Pro.
- `.npmrc` sets `engine-strict=true` (Node version constraints are under Commands).
